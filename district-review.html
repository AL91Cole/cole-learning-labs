Data in brief

Public activities open without an account, a roster or a class code. The scenarios, requesters and sample files are fictional. Some labs use a real hosted Linux machine instead of a browser simulation.

What stays in browser memory

In browser simulations, lab work starts in the memory of the open page: the clues collected, questions asked, typed notes, answers, workbench state and the report text built from them. The site does not upload it. It is gone when the tab closes or reloads, or when the learner clears it, unless the learner turned on device saving first.

What leaves the browser in real-machine labs

Start machine sends the lab ID, screen dimensions, the device’s time zone, session messages, keyboard and pointer input, text pasted into the machine and check requests through Cloudflare to a DigitalOcean controller and Docker Cloud Sandbox. The hosted machine processes files and commands and returns its screen or terminal output; the controller reads selected lab files and recent command history for progress checks. Use fictional details only. No camera, microphone, other-tab or local-screen capture occurs. Machines are offline unless the operator turns on online labs: then networking and security labs reach example.com and, with filtered browsing, other websites through a family-safe DNS filter that receives the names looked up. That traffic does not pass through the school’s network or web filter. Read the remote processing and deletion limits before school use.

Stop, disconnect and timeout trigger deletion requests. Cleanup can fail or be delayed, and provider logs or recovery copies have separate retention. Clearing local work does not prove remote erasure. Starting a machine does not establish parental consent or school authorization.

What optional device saving does

Lab work is saved on the device only after the learner chooses it. The learner selects Save on this device, ticks a confirmation that this is their own approved browser profile, and selects Enable device saving. Where a copy was saved before, Resume saved work asks for the same confirmation, loads that copy and turns saving back on. The lab records are then kept, unencrypted, in this browser’s local storage on this device, under keys that begin cole-learning-labs:. They are not sent to the site. Anyone who uses the same browser profile can read them. Clear local lab data in the same panel removes them. Pausing saving does not delete a copy saved earlier.

Display menu choices (text size, spacing, contrast, motion) are also kept in local storage on the standard page. They hold no learner work.

How shared-device work is cleared

Open the site with /?cart=true. The page is never given the browser’s local storage, so no work is saved, an earlier saved copy is not offered and display choices are not kept. After 40 minutes without activity the page clears its work and returns to the home page. A warning with a Keep working button appears at 38 minutes. Time with the lid closed counts, so a device woken after the limit clears before the next learner starts. Clear this page now in the strip at the top does the same on request.

It does not clear work saved earlier from a plain link, downloaded reports or the clipboard. The offline cache of public site files is separate and holds no learner work.

What Cloudflare receives during ordinary delivery

Cloudflare hosts and protects the site. As with any website, each request gives the host the IP address, the requested path, browser information, and security and traffic metadata. Using the site without an account does not prevent this.

Lab addresses are hash routes such as #lab/INC-101. Browsers do not send that part of an address to the server.

The lab application makes these availability checks to its own website: one request to /api/reach when the page loads, and one to /api/telemetry when an activity opens. They carry no learner work, no cookie and no referrer. With the current configuration both answer that the service is off. The /api/reach check is skipped when the browser sends Global Privacy Control or Do Not Track. Real-machine support also checks /terminal/api/health and, when enabled, /terminal/api/labs; those checks attach no learner work. For the host’s own processing, see Cloudflare’s privacy policy on cloudflare.com (opens in a new tab).

What an export contains

My report shows the whole report for the learner to review before anything leaves the page. It leads with a four-line summary (clue, change, result, next step) made from the learner’s own entries. The full record holds:

  • the lab ID and title, grade band, topic and status
  • the original task
  • the clues collected
  • the questions asked, with the authored replies
  • the learner’s typed notes: symptoms, working hypothesis, test notes and reflection
  • the experiment record and the action log
  • in hardware labs, the cable connections
  • in coding labs, the practice code and its output

After ticking a review confirmation, the learner can copy the text or download a UTF-8 .txt file named with the lab ID, for example cole-learning-labs-INC-101.txt. Some devices also offer their own share sheet. The site adds no name to the report or the file name. A report holds personal details only if the learner typed them, and the site does not detect them.

What leaves the site when someone chooses an outside destination

A downloaded or copied report goes wherever the person puts it: the district LMS, a drive, an email. From then on that system’s rules apply, and the site cannot recall the copy. Some investigations show an optional Google Classroom share link. It passes Google the public lab address only: no notes, alias, roster or grades. Links to other websites open without a referrer. In student mode, links to other websites are turned off.

A no-account school pilot

This is a proposed way to try browser simulations with one class. The example hardware lab stays local; starting a real machine adds the remote flow described above and needs separate district review. It is a plan, not a report.

  • Requester replies: built-in authored replies only. Online replies are not offered.
  • Classroom records: connected collection remains off. No accounts, rosters or grade sync. Remote machine input is still transmitted if that feature is used.
  • Submissions: the learner reviews the report, downloads the .txt file and hands it in through the district’s approved LMS.
  • Device saving: off by default everywhere, and unavailable with the shared-device link.
  • Launch: the existing combined student-mode and shared-device link below.

Enforced

By the build or the code. A hosting setting cannot undo these:

  • Online requester replies are removed from the public build.
  • Classroom collection and improvement summaries are locked in source.
  • With the shared-device link the page is never given the browser’s local storage. There is no Save control and no resume, and the page clears after 40 minutes without activity.
  • With the student-mode link the portfolio, contact, teacher-resource and sign-in pages are hidden and links to other websites are turned off.
  • No account, roster or grade-sync feature exists to switch on.

Set by hosting configuration

The operator can change these without a code release:

  • Aggregate activity counts, lab telemetry and signed completion codes are off in the hosting configuration.
  • The reply gateway is still enabled on the server in production. The published page does not call it.
  • The terminal gateway is configured; a responsive controller can offer Start machine. Student mode and shared-device mode do not block remote processing.

Not enforced

These stay with the district, the teacher or the learner:

  • The link is a convenience, not access control. A learner can open the plain address and choose device saving.
  • Work saved earlier in that browser, downloaded reports and the clipboard stay until someone clears them.
  • Web filtering, device policy and separation between classes are the district’s, for example ChromeOS ephemeral mode or managed guest sessions.
  • Cloudflare still receives delivery metadata, including the IP address.
  • The availability requests described above still go out with these links.
  • The offline cache of public site files is still installed, and ?mode=student&cart=true is part of the requested address.
  • What a learner types. Ask for fictional details only; the site does not detect personal information.

The pilot is not a data-sharing agreement and not a research study. It has not been run with a school, and the site receives no learner work from it. A classroom plan for teachers is on the troubleshooting pilot page. More on the two link modes is under “Classroom link options” in the School IT review.

Managed Chromebook test checklist

Run these on a real managed Chromebook, signed in as a test student on the student network. Use fictional test content only.

  • Allow https://www.colelearninglabs.com for the student organizational unit, and confirm colelearninglabs.com redirects to it.
  • Open one lab on the student organizational unit and network: The Blank Monitor.
  • Work one step with the keyboard only, then with touch. No step needs a precise drag.
  • Set the browser to 200% zoom and confirm the lab controls can still be reached and read.
  • Open the Listen and Display tools in the bottom-left corner. On smaller screens they show as icons only: a speaker and “Aa”. Change the text size, then start and stop reading. Listen uses only voices built into the device.
  • Open My report, tick the review confirmation, choose Download .txt report, then open the file from the Files app. Find and open files, on support.google.com (opens in a new tab).
  • Open the combined link /?mode=student&cart=true#lab/INC-101. Confirm the strip names both modes, the adult navigation is hidden, an outside link no longer opens and the lab’s saving panel has no Save control.
  • Select Clear this page now, confirm, and check that the lab is empty and the page is back on the home screen.
  • Leave the page untouched. Confirm the warning at 38 minutes and the clear at 40. Repeat with the lid closed past 40 minutes, then reopen.
  • With challenges.cloudflare.com blocked, confirm the labs and built-in replies still work.

ChromeVox and the device’s own read-aloud should be checked on a real managed Chromebook. The site’s recorded device checks were made in desktop browsers and resized windows, which do not reproduce a managed device, a school filter or assistive technology.
