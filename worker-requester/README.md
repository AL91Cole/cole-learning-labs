# Optional fictional requester Worker

This is a separate, disabled-by-default service for **a verified Workers Free account**. It does not change the website's existing account or billing. Do not deploy this service to Workers Paid when an enforced free allowance is required. The environment assertion cannot inspect the subscription or prevent a later plan upgrade.

The browser sends only a known fictional `scenarioId` and an authored `topic` ID. The Worker rebuilds the prompt from the shipped fictional character card and topic template. It rejects extra properties, including questions, names, notes, history, records, model choices and token limits. Unknown topics stay offline. No learner's question or conversation is sent to the model. Cloudflare still receives the selected topic, fictional lab ID and ordinary request metadata; this is an external service, not an offline feature.

Generated replies are extra ungraded conversation. They cannot supply canonical case clues, advance progress, change evidence or enter reports. Output checks reject obvious private details, HTML, code blocks and links, then bound plain text to 600 characters. These checks cannot guarantee model accuracy. Authored local conversation remains available when AI is disabled, busy, unavailable or out of quota. This service does not open the classroom records API or approve student-record processing.

## Deployment configuration

1. Independently verify that the deployment account's **Workers plan** is Free. A domain's Free zone plan does not establish the Workers plan. If no suitable account is available, leave this service disabled. Account creation and any plan changes require a separate decision.
2. Use the supplied `wrangler.jsonc` as the deployment configuration. It contains no account ID or credentials. Select the verified account explicitly through your normal authenticated Wrangler or dashboard workflow. Do not commit a token, add a paid model, buy Gateway credits, upgrade the account, or route inference through a Paid-account proxy.
3. Keep the single `AI` Workers AI binding. No KV, D1, Durable Objects, AI Gateway, remote provider or paid API key is needed. This Worker uses one fixed `@cf/meta/llama-3.1-8b-instruct-fp8-fast` call, capped at 140 output tokens, without retries.
4. Set `REQUESTER_ALLOWED_ORIGINS` to an exact comma-separated HTTPS list. The template includes the production `www` and apex origins. Add only specifically reviewed Pages preview origins when needed. No wildcard, suffix matching, localhost, HTTP, IP origin, URL path, port or credentialed request is accepted. A malformed entry closes the entire list. CORS limits cooperating browsers; it is not authentication and does not prevent a non-browser caller from consuming the free allowance.
5. Only after the account, fictional-only data flow and deployment have been checked, set both `REQUESTER_FREE_ACCOUNT_CONFIRMED` and `REQUESTER_ENABLED` to the literal string `true`. These are operator assertions, not automatic billing detection. Leave either false to disable the service. Disable it before any plan change.
6. Configure the website to call `https://<deployed-worker-host>/api/requester` directly with `credentials: 'omit'`. Allow only that exact service origin in the site's `connect-src` policy. Keep availability checking, explicit consent and opt-in mode in the browser; no call should occur on page load. A successful availability GET does not generate a reply. Test with fictional topics before enabling the option for visitors.

The endpoint accepts GET for availability, OPTIONS for an allowed CORS preflight, and POST with exactly `{"scenarioId":"INC-101","topic":"breakfast"}`. POST requires JSON, no URL query, and at most 600 UTF-8 bytes. It never returns cookies or `Access-Control-Allow-Credentials`. Requests with cookies or Authorization are refused. Responses use `Cache-Control: private, no-store` and `Vary: Origin`. Logging is disabled in the template, and the handler does not log prompts or provider errors. Deployment tooling may still retain ordinary operational metadata under the provider's policies.

## Quotas and operating limits

Cloudflare currently includes 10,000 Workers AI neurons per day on Workers Free; usage beyond the Free allowance fails rather than automatically becoming Paid inference. The Free Workers request limit is 100,000 per day. Limits reset as documented by Cloudflare. These are account-wide provider limits, so other services in that Free account share the allowance. Remain on Workers Free and recheck the provider's current terms before activation. Workers Paid can bill AI usage beyond its included allowance; an alert, CORS rule or this program's counters cannot impose a Paid-account spending cap. [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/).

Anonymous in-memory backstops allow at most two unfinished inferences, 12 starts per minute and 500 starts per UTC day **per isolate**. They retain no IP or learner ID, and reset with an isolate restart. They are neither global limits nor a spending cap. Quota, capacity, rate-limit, timeout and provider failures return a fallback without retry. A timed-out request may still finish at Cloudflare; its concurrency slot remains occupied until it settles. The Free account's enforced allowance is the billing boundary. This service cannot cap or change charges for unrelated products or a separate Paid account.

A real Workers AI binding, including some local development modes, can use the account's actual allowance; do not use live inference as a test before configuration review. [Workers AI bindings](https://developers.cloudflare.com/workers-ai/configuration/bindings/), [Workers AI data usage](https://developers.cloudflare.com/workers-ai/platform/data-usage/).
