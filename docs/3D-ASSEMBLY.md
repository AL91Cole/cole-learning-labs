# Assembly workbench

The filename is retained for existing documentation links. The current interface restores the simpler PR #6 visual style and removes the 3D renderer. Equipment is an original, labeled 2D SVG diagram with ordinary HTML controls. There is no WebGL requirement, camera movement, graphics download or decorative pathway station.

## What is retained

All eight hardware investigations and the beginner hardware lesson use the current models. Opening an investigation workbench adopts detailed checks once without repairing its fault or discarding notes, conversation, evidence or progress. Existing detailed saves retain their equipment and mechanical state. The other four pathways keep their actual software workspaces, tests and report flows.

The model retains eight removable parts, 18 screws, case access, CPU retention, DDR4 clips, PCIe latch, cooler fan lead and thermal-paste preparation. A component or tool selection alone does not change equipment. Native buttons request the same documented actions as diagram interaction. Power off and disconnect virtual AC before internal work. Follow mount, fastener and compatibility checks; the cooler screws use the model's cross pattern. Removing a cooler disturbs its paste, requiring cleaning and fresh paste before a valid rebuild.

## Connections

Ten independently selected cable ends use fixed matching socket mappings: AC; PC HDMI; monitor HDMI; 24-pin ATX; 8-pin CPU power; GPU power; SATA data; SATA power; front-panel switch; CPU fan. Both HDMI ends and the monitor input must be correct. Reconnecting one end does not silently repair the other. Internal cables require safe power and case access. Invalid selections and wrong sockets cannot dispatch arbitrary actions.

The original classroom SSD and files are preserved. A successful startup alone does not finish the ticket: open the original lesson document and complete the student's evidence and explanation. Reports retain screws, clips, paste, cable endpoints, source selection and original-task evidence.

## Interaction and accessibility

The workbench uses the PR #6 dark teal/navy schematic style. Choose a component, read its state and use a labeled control. Part, tool and extended-help disclosures keep the main view compact. Keyboard and touch controls provide alternatives to precise diagram targets or dragging. Escape, opening a report, hiding the workbench and replacing the route cancel unfinished interactions without changing accepted model state. A section return preserves existing equipment and notes.

These are authored teaching checks, not physical collision, screw torque, measured paste spread, electrical behavior or heat simulation. Teacher answer keys and assessment rubrics remain outside the public repository. Student reports are reviewed before local export; live AI and connected classroom collection remain unavailable pending review.

## Verification

Retain model, complete-build/teardown, screw-order, safe-power, paste-rework, malformed-save, schema, experiment and report regressions. Diagram/controller tests cover state-driven equipment, native tool/cable controls, wrong selections, cancellation, focus and disposal. Packaging tests ensure neither static nor dynamic runtime imports reach an engine or obsolete scene, and no vendor engine is shipped.

Responsive browser checks are useful but do not establish physical Chromebook, tablet, Edge or assistive-technology performance. Record release-specific evidence and school-device acceptance checks in [Device checks](DEVICE-CHECKS.md).
