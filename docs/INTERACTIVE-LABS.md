# Interactive workbenches

Choose a practice workbench in the lab catalog to start with the controls. Networking, AI and cybersecurity practice use the existing fictional models with optional task clues. Switch cases within a pathway or return to a guided investigation. Practice state stays in page memory, separate from guided records and classroom submissions.

## Build a network of your own

Open `#studio/network` from the networking catalog or practice workbench. Start with the classroom layout or an empty canvas. Add PCs, switches, routers, servers, access points and printers; move devices; choose endpoints; and connect free ports. Remove a cable or device, or turn a device off, to compare the result. Removing a device also removes its attached cables.

The live connection checks are derived from the current graph after every edit. A packet follows the computed route through powered forwarding devices. A successful demonstration shows the outgoing message and modeled reply; a broken path shows the reached devices and a failure point. Send, replay and animation controls support repeated observation. Reduced motion keeps the same result and an ordered path without movement.

This is a bounded topology and forwarding activity. It does not send real packets or emulate a full IP stack, routing protocol, wireless radio, or network security policy. The course investigations teach those additional settings separately. Device types, ports and graph size are limited to the supplied simulation. Free layouts stay in page memory across normal site navigation and clear on reload, closing, or local-data clearing. They do not enter guided reports or classroom uploads.

## Move and cable a course network

In the ten networking sequence labs, drag a device or use the four labelled move buttons. Positions snap inside the drawing and avoid device overlap. Move actions preserve the current test because location on the page does not change addressing or routing.

Select matching cable ports to connect them. Select a cable or use the labelled Disconnect button to unplug it. A cable change affects connectivity and invalidates the current test. The PC layout, backup-link plan and local-link setting follow their corresponding physical gesture. Reconnecting a redundant switch link does not silently enable spanning tree.

In the course investigations, ports and cable pairs are supplied by the activity. Use Network Studio to add or remove devices and choose other connections. Neither mode accepts real destinations or executable commands. The course diagrams also provide a local test-packet demonstration. Saved configuration or cable changes refresh the trace; layout-only moves and inspections do not start a new packet. A physical-path demonstration never replaces the full lab test or earns completion. Layer labels, policy evidence and supplied packet records remain distinct from physical cabling. Keyboard and labelled button alternatives support the same actions as dragging.

## Act on the other workbenches

Action cards expose the current task controls for legacy network/OS, AI and cybersecurity cases. Each button applies a supported model action; it does not bypass scope acknowledgement, perform a real network operation, or award a successful test. Detailed settings remain available when useful. Inspections preserve pending settings. Guided investigations still require their saved learning artifacts.

## Create in Coding Studio

Open `#studio/coding` to choose message art, a scoreboard, a calculator, a decision display, or a blank program. Change the source and numeric inputs, run it, and inspect text or number bars. Editing source or inputs clears the old preview. Normal site navigation preserves the draft in page memory; reload or closing the page clears it. The page warns when practice work may be lost.

The studio parses a deliberately small language. It does not evaluate JavaScript, load packages, open files, contact networks, or send text to an AI model. Comments and strings stay data and cannot grant permissions or change the interpreter's rules. Output is rendered as text or bounded numeric bars.

The interpreter has independent limits for source length, tokens, nesting, repeat counts, variables, execution steps, output lines and string lengths. Inputs are finite primitive values from known controls; accessors and host objects are rejected before execution. Unsupported syntax fails closed. These controls reduce available capabilities but do not establish an impenetrable system or eliminate the need for review.

The implementation follows the separation described in [OWASP safe output guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html) and avoids string execution described in [MDN eval guidance](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/eval). This work does not change the requester live-AI configuration. The real-classroom release gate remains closed.
