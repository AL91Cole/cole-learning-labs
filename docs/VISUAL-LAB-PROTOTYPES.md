# Visual building and block-programming prototypes

These original interactions combine a parts/workspace/test layout, cable building and guided block programming. The first version introduced the full PC assembly investigation and three free elementary coding workshops; the expansion brings visual repair to five more PC investigations, blocks to the six existing coding investigations and drag connections to ten guided network investigations. Interaction references are [Tinkercad Circuits](https://www.tinkercad.com/circuits) and [Tynker's guided coding activities](https://www.tynker.com/parents/curriculum/creating-with-code/). No third-party editor, assets, account system or service is embedded.

## Build a classroom workstation

The full build layout applies to the existing member/owner investigation `INC-106`. A parts tray, the existing interactive PC drawing and a live test panel sit beside one another on wider screens and stack on smaller screens. Investigations `INC-101` through `INC-105` use the same visual arrangement with repair observations appropriate to their existing equipment and relevant controls. Existing tools, part placement, cable connections and keyboard/touch alternatives retain their model-controlled actions.

Build, Connect and Power & test observations derive from the current equipment state. Fitting a part is separate from securing its screws, clips, retention or thermal interface. A running fan does not establish successful startup. A visible desktop is separate from checking the original lesson file. Changing equipment can invalidate earlier observations; the guide does not save completed stages or automatically fix equipment.

The existing power and case-access interlocks remain authoritative. The display is an authored teaching model, not real equipment control or a general CAD/electronics simulator.

The shared Power and AC controls stay above the monitor for every PC workbench, exactly once. Repair readouts describe the current screen, safe-work state and original-file check; they do not invent completed inspection milestones or treat every repair as an empty-PC build.

The full-build markup and progress helpers remain in `src/assembly-builder.js`. The public compiler substitutes exact inert exports for that module. Generic repair layout in the shared workbench is available to the two existing free hardware cases; paid case briefs and specialty actions remain filtered. The full builder remains on its protected case route. Delivery tests continue to check the absence of authored member payloads in the public artifact.

## Build a tiny program

The existing free activities `EX-CODE-1`, `EX-CODE-2` and `EX-CODE-3` gain an optional block workshop beneath their prediction challenges:

- K–1 moves a picture robot along five spaces with fixed direction and Show blocks.
- Grades 2–3 set a counter, add, repeat an addition and show the result.
- Grades 4–6 also test an if/otherwise decision against the current counter.

Learners can use a drag handle to insert or reorder blocks, or use Add, Move up, Move down and Remove. Run shows the computed result; Step exposes the trace one model operation at a time. Editing clears stale results. Clear and Restore example belong to the workshop; the original prediction challenge's Check, Next and Reset controls remain independent. Neither completing a program nor reaching a value awards a grade or completes the prediction task.

The workshop interprets only validated, known instruction objects. It does not execute JavaScript, generated source, arbitrary labels or uploaded content. Programs have at most 12 blocks and 80 model steps; numeric results stay between -100 and 100, with the younger robot constrained to its five spaces. Repeats and decisions are deliberately small authored teaching operations. The displayed instruction list is explanatory text, never executable code.

## Repair an investigation with blocks

The six older coding investigations (`CODE-501`–`CODE-506`) offer **Build this program with guided blocks** beside the existing editor. Their authored starter blocks retain a problem to investigate: arithmetic, room-mode boundaries, readiness indexing, energy calculations, prize thresholds or accumulation. The first two stay free; the other four retain their member restriction. Each case's block contract remains inside the same tier-filtered definition as its existing fixtures and starter source.

Learners can add, drag, reorder, remove and change fixed choices in a program of at most eight blocks. The generator accepts only those reviewed instructions and emits at most 4,000 characters of the existing limited JavaScript/Python language. **Preview all inputs** runs through the existing bounded interpreter and fixture comparison without awarding an official result. **Copy blocks into editor** explicitly replaces the editor draft; the learner still runs the original checks and follows the existing save/report choices. The interpreter, task goals and verification rules remain authoritative. Block edits clear the preview. Same-investigation redraws preserve the temporary block arrangement; leaving or disposing the investigation clears it.

## Connect a guided network

The ten existing guided network investigations (`NET-207`–`NET-216`) support dragging a labeled port onto its matching port. A preview line and target highlight show the pending connection; release requests the same reviewed connect action as the existing native controls. Unrelated ports cannot create arbitrary links. These remain member investigations with their original network goals and checks.

Two-port selection, keyboard controls, inspector Connect/Disconnect and existing device positioning remain available. A canceled or interrupted gesture leaves the saved plan unchanged. Outside drop data is ignored. The activity is an authored browser model and does not contact a real network, discover devices or inspect connection information.

## Privacy, access and operation

The elementary workshop has no free-text input, account, storage, network call, external drag-data import or telemetry. Its draft exists only in the mounted activity's memory and is discarded on navigation/disposal. Drag cancellation, lost capture, blur and cleanup cannot commit a partial placement. Learners can use the fixed controls without dragging.

All 15 elementary activities remain free. The older five beginner courses, two free investigations per topic and free-case workbenches keep their access policy. Full studios, open coding sandboxes, other investigations and teaching resources remain restricted; the owner's separately protected full workspace remains a distinct delivery path.

No prices, live billing, classroom access, student-data collection, improvement sharing, cloud-AI contract, AI budgets or provider account settings are activated or widened by this source change. No dependency, plan or paid add-on is added. Ordinary builds continue to publish only the reviewed free artifact. Public release remains subject to review and merge; any full owner preview must retain the existing Access guards and must never be promoted to production.

## Owner sign-in entry

The navigation, footer and membership notice provide an **Owner sign in** link to the existing protected owner workspace. This is a normal link with no automatic request or identity form. The existing server-side Access policy verifies the approved owner before any private page, script or resource opens. A public button, query flag or local browser value never grants access. Owner access needs no subscription or payment and does not activate the separate membership backend.
