# Search indexing and preferred URLs

The reported Search Console URL is `https://www.colelearninglabs.com/`, with **Duplicate without user-selected canonical**. This means Google grouped it with another URL and selected a canonical without an explicit preference from this page. The affected URL alone does not identify the duplicate Google chose; inspect the indexed URL details before attributing the result to a particular hostname.

Source review found no canonical link on the homepage, no sitemap or robots file, and a School IT canonical pointing to `.html` even though Cloudflare Pages normalizes HTML filenames to extensionless paths. Browser inspection also confirmed that the live `www` homepage and `https://cole-learning-labs.pages.dev/` both served the homepage without a canonical; the production Pages hostname did not redirect. The HTTP apex `http://colelearninglabs.com/` already reached HTTPS `www`. The public Pages copy is a plausible duplicate contributor, but Google's actual selected canonical is still unknown. These are concrete inconsistencies addressed in this change. Recheck live responses after publication and inspect Google's selected canonical in Search Console.

## Signals defined in source

- `index.html` declares `https://www.colelearninglabs.com/` as its canonical and Open Graph URL. Hash routes such as `#labs`, `#guide`, and `#lab/INC-101` remain usable browser navigation; they are not separate sitemap or canonical URLs.
- Other public content pages use their matching extensionless production canonical: `/school-it`, `/student-workbook`, and `/practice-quizzes`. Each page identifies itself, rather than consolidating different content into the homepage.
- The classroom entry, encrypted-report tool, teacher entry, and error page retain or receive `noindex` because they are utility pages. They are omitted from the sitemap. This choice is independent of duplicate-URL consolidation.
- `sitemap.xml` contains only the four preferred public content URLs. `robots.txt` announces that sitemap and permits crawling so Google can see canonical and noindex directives. Neither file contains work, keys, student data, or private teaching resources.
- `_redirects` permanently consolidates `/index.html` and `/index` into `/` with relative destinations. Cloudflare Pages already redirects other `.html` paths to their extensionless equivalents. Relative destinations keep branch previews on their own host and preserve normal hash navigation.
- Production canonicals remain in preview HTML as a preference for the published copy. Previews are still usable for testing. Canonical hints are not access controls or a guarantee against indexing.

Google describes redirects and canonical links as strong signals and sitemap inclusion as weaker support. It can still choose a different canonical. See [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) and [Cloudflare Pages route matching](https://developers.cloudflare.com/pages/configuration/serving-pages/).

## Security change in the same release

The main public CSP previously restricted outgoing frames (`frame-src 'none'`) but did not restrict websites embedding the labs. It now also declares `frame-ancestors 'none'`, with `X-Frame-Options: DENY` as a compatibility backstop, covering all static pages. This reduces clickjacking risk around simulated controls and saved-work actions. Open labs as full browser pages; embedding them in an LMS iframe will be blocked after deployment. Report and teacher pages already had the CSP restriction.

The public browser app still has no third-party runtime package dependencies. Source review retained the topic-only requester's fixed payload, bounded streamed request body, exact origin checks and shared admission ledger, and the hardcoded closed classroom-privacy gate. Those source controls do not establish current provider settings or a complete security audit. Account access, CI security findings, optional terminal dependency audits, deployed headers, and school-device testing remain separate release checks. See [repository security](REPOSITORY-SECURITY.md).
